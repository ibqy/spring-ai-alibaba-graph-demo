# 实现边界：什么是真的，什么是模拟的

## 先看这张表

| 内容 | 实现方式 | 不代表什么 |
| --- | --- | --- |
| 图定义与执行 | 原生 `StateGraph` / `CompiledGraph` | 不是手写 switch 冒充 Graph |
| 分支、循环、并行、子图 | 由 Graph 实际调度 | 不是只能看图、不能运行 |
| 检查点 | `MemorySaver` | 不跨 JVM 重启、不跨实例共享 |
| 审批中断与恢复 | interruptBefore + updateState + withResume | 不包含企业身份认证和审批权限系统 |
| 节点 SSE | 实际节点执行事件 | 不宣称是 LLM token 流 |
| 默认模型 | 确定性 Java 教学实现 | 不是大语言模型，也不具有通用理解能力 |
| DashScope 模式 | 配置密钥后真实调用 qwen-plus | 不保证输出正确，调用可能计费 |
| 工单知识检索 | 本地固定资料的关键词匹配 | 不是向量数据库或完整混合检索系统 |
| 报销信息抽取 | 明确格式的文本规则 | 不包含 OCR、发票真伪查验 |
| 报销入账 | 进程内模拟凭证与幂等记录 | 不会连接银行或真实付款 |
| 研报资料 | 固定的教学资料 | 不是实时联网调查结果 |
| 审核后发布 | 返回进程内生成的产物 | 不向外部平台发送消息或文章 |
| 网站部署 | GitHub Pages 静态文档 | 不托管 Java 服务或 API Key |

## 为什么默认允许无 Key 运行

图机制与模型生成是两种不同的学习问题。没有 Key 的学习者也应该能验证路由、检查点和并发是否正确；CI 也不应该依赖外部付费模型的可用性。

离线模式是明确的教学路径，不是模型调用失败后的静默降级。启用真实模型但密钥缺失时，应当失败并提示，而不是悄悄返回一段模拟答案。

## 运行记录的生命周期

统一运行器为每次执行创建独立的图运行实例和 MemorySaver，用生成的 `executionId` 作为 `threadId`，恢复时复用原实例。

- 内存最多保留 100 条运行记录。
- 达到上限时优先淘汰最早的已结束记录。
- 若全是运行中或待审核记录，拒绝新增执行并返回 429。
- 淘汰或服务重启后，旧 executionId 查询返回 404。
- 业务模拟幂等记录也不提供重启后的持久性。

这适合本地教学，不适合无限期等待的线上审批。

## 副作用与 exactly-once

重新执行节点可能重复触发外部副作用。检查点保存了图状态，并不能代替下游数据库事务、唯一约束或业务幂等键。

本项目演示进程内原子幂等与重复请求冲突，但没有跨节点事务。不要把一条单机测试通过理解为分布式 exactly-once 保证。

生产中的付款、邮件发送、订单创建等动作，通常需要持久化幂等记录、唯一约束、发件箱模式或可查询的外部操作编号。

## 并发与取消

并行节点应当返回可合并的增量，避免共享可变对象。追加结果的顺序不应作为业务保证，测试应该断言结果完整而不是线程先后。

运行器设置图执行上限和流等待超时。HTTP 客户端断开或流超时，不保证已经开始的外部请求立刻停止，更不保证副作用回滚。

## 安全范围

服务默认只监听 `127.0.0.1:8098`，用于本机学习。

- 没有登录、用户授权、租户隔离、审批人身份校验。
- 随机 executionId 是关联标识，不是完整授权机制。
- 恢复请求只允许布尔审批结论，不接受任意状态覆盖。
- 初始输入只允许示例公开字段，防止注入内部审批状态。
- 密钥仅从环境变量读取，不写入源码、文档构建或浏览器。
- 不要直接将该服务暴露到公网；不要输入个人敏感信息、真实发票或公司机密。

切换 DashScope 后，模型节点的提示词和资料会发送给模型提供商。使用前确认数据可以外发。

## 版本不是“越新越正确”

本项目锁定 Graph / DashScope 1.1.2.2、Spring AI 1.1.2 与 Spring Boot 3.5.8，目的在于使示例可以针对一组明确版本验证。

这不表示它们是最新版本，也不表示整个 1.1.x 系列的 API 都完全兼容。升级后应重新运行测试，特别关注人审恢复、状态序列化与并行合并。

## 进一步走向生产

在这份学习代码之上，至少还需要补齐：

1. 身份认证、审批权限与操作审计。
2. 检查点持久化、数据库迁移、版本兼容和多实例并发控制。
3. 外部副作用的事务边界与持久化幂等。
4. 任务队列、流量控制、成本预算、模型调用超时与重试策略。
5. 敏感数据脱敏、提示注入防护与模型输出验证。
6. 可观测性、告警、容量规划和故障恢复演练。

这些是明确的后续方向，不是本项目已经实现的功能。
